Part 1 · Meet Hermes

A chatbot answers. An agent acts.

  • Same model, different loop. What makes it an agent is the loop around the model.
  • Every loop costs tokens. A 5-step task can cost more than a long essay.
  • Mistakes become actions. A wrong answer is text; a wrong tool call changes things.

Part 1 · Meet Hermes · A question students ask

“I can already make a Telegram bot. Why Hermes?”

  • BotFather gives you an empty account, not a brain. Every reply is code you still have to write.
  • Hermes is the agent behind the bot, and the same agent also answers in Discord, Slack, the terminal, and apps.
  • Honest answer: for a fixed menu bot, a plain bot is simpler. For a helper that thinks, remembers, and acts, use Hermes.
In one lineThe Telegram bot is the phone line. Hermes is who answers.

Part 3 · Make your own agentTERMINAL

Your whole agent is one folder

  • Backup = copy one folder. Everything is in ~/.hermes.
  • .env is hidden. Its name starts with a dot, and it’s the one file never to share.
  • Profiles are full copies. Each has its own folder, memory, and keys.
Try itls ~/.hermes
~/.hermes/profiles/h101-researcher/ config.yaml # model, tools, safety .env # secrets: keys, tokens SOUL.md # who it is memories/ # what it remembers skills/ # saved how-tos cron/ # scheduled jobs

One profile = one agent = one job

  • Isolated by design. Your study buddy can’t read your coder’s memory.
  • One gateway, many agents. Each profile gets its own address.
  • Add -p name to any command to aim it at one agent.

Part 3 · Make your own agentTERMINAL

SOUL.md: who your agent is

  • Read at the start of every chat. Edit it, type /new, see the change.
  • Short beats long. Ten clear lines work better than a page.
  • A rule is a request. A tricky web page can talk the agent out of it.
Try it~/.hermes/profiles/<name>/SOUL.md

Part 3 · Make your own agentHERMES DESKTOPTERMINAL

Every tool is a door

  • Tools are set per platform. Telegram can have fewer than your terminal.
  • The risky four: terminal, files, browser, and code execution.
  • Changes need a new chat. Running chats keep their old tools.
Try ithermes tools

Part 3 · Make your own agentHERMES DESKTOP

A rule is a request. A setting is a lock.

  • Approval Mode makes risky commands wait for your yes.
  • deny beats approve. A denied command can’t run even if clicked.
  • max_turns is your cost cap. It ends loops before they burn credits.
Try ithermes config set agent.max_turns 20
approvals.mode: manualRisky commands wait for you
approvals.deny: ["rm -rf *"]Never runs, even if approved
agent.max_turns: 20Stops runaway loops
